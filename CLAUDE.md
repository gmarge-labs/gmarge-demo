# CLAUDE.md — ground rules for gmarge-demo

These rules apply to **every** task in this repo. Read them before doing anything
else, and follow them without needing to be reminded.

## 1. Clean-room build

Write everything in this repo from scratch. Never reuse or adapt code, prompts,
schemas, column names, metric definitions, copy or visual designs from any
employer, client or other private codebase. If a task seems to call for
recreating something proprietary, stop and ask.

Public, standard concepts (incremental ROAS, geo holdouts, difference-in-
differences, GA4's `source / medium` convention) are fine — the *implementation*
must be original.

## 2. No live AI calls from the public app

The Streamlit app must never call an AI API at runtime. The flow is:

```
offline script  ->  human review  ->  readouts/*.md (or .json)  ->  app reads files
```

AI read-outs are generated **offline**, checked by a human, and committed to
`readouts/`. The app only reads saved files from that directory. No `anthropic`
import in app code paths; `anthropic` is used solely by offline generation
scripts.

## 3. Python computes every number

Every number a user sees — totals, ratios, ROAS, lifts, deltas, percentages,
dates — is computed in Python and passed to the model as a fact. The model's
only job is to phrase facts that are already computed. It never does arithmetic,
never estimates, and never invents a figure. Prompts pass explicit numbers; the
read-out is checked against the computed values before it is saved.

## 4. Secrets

Secrets live only in a git-ignored `.env` file, loaded with `python-dotenv`.
Never commit keys, never hard-code them, never print them in logs or notebooks,
and never paste them into code comments or test fixtures. `.env.example` (no
real values) documents which variables are needed.

## 5. Minimal, pinned dependencies

The dependency set is exactly:

    pandas, numpy, pyarrow, streamlit, altair, anthropic, python-dotenv, pytest

Every version is pinned in `requirements.txt`. Adding a dependency requires an
explicit ask — prefer writing the 20 lines yourself over pulling in a library.

## 6. Data in this repo is fictional sample data

The brand "Northfield Goods (sample brand)" does not exist. All data under
`data/` is synthetic, generated by `gmarge/generate.py` from a fixed seed. Never
describe it as real, and never present it as any real company's numbers. Keep
that disclaimer visible in the README, the app and any read-out.

## 7. Reproducibility

`gmarge/generate.py` is seeded and deterministic: same seed in, byte-identical
figures out. Anything that makes generation non-deterministic (unseeded RNG,
wall-clock time, dict ordering, set iteration) is a bug. The planted "truths"
live in `data/truth.json` and are what the tests assert against.
